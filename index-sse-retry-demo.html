Server-Sent Events (SSE) Retry Header Demo

Testing SSE retry behavior with different connection modes

How it works:

• The server continuously generates events every 2 seconds, even when no client is connected.

• When a client connects, it receives all accumulated events immediately.

• The server sends an id: field with each event. On reconnection, the browser automatically sends this as the Last-Event-ID header.

• The server reads Last-Event-ID and replays only the missed events.

Connection modes:

• Start Connection: Standard SSE with chunked transfer encoding

• Start (Content-Length): SSE with Content-Length header
